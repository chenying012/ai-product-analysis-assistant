# 品析 · AI 产品分析助手

输入一个公开的 Amazon 商品链接，得到**结构化商品档案**、**目标人群/场景/痛点/卖点分析**，以及一条**150 字以内的中文短视频口播**。

整个流程在服务端完成，前端只负责输入与展示。核心设计目标不是"接一个模型把链接丢进去"，而是让 **AI 只能使用页面上真实存在的信息**，并且在它说不清楚的时候**如实承认**，而不是编一个看起来完整的答案。

## 它解决什么问题

做跨境电商短视频时，一条口播文案的前置工作通常是：打开商品页 → 读完功能列表和规格表 → 判断卖给谁、在什么场景下用、解决什么痛点 → 再压缩成 30 秒能念完的中文脚本。这件事重复、耗时，而且容易在压缩过程中丢掉前提条件，写出夸大的表述。

本项目把这个流程自动化，同时刻意保留了两个人工环节无法替代的约束：

1. **不编造事实。** 商品信息全部来自页面解析，不经过模型。取不到的字段（比如价格）保持为空并说明原因，绝不用默认值或"参考价"补齐。
2. **不放过夸大表述。** 生成的文案会经过一套确定性规则检查，拦住绝对化措辞、效果承诺、材料以外的数字、以及被丢掉的前提条件。有问题会把具体短语退回模型改写。

### 功能清单

- 严格校验 Amazon 站点白名单（20 个区域站）与 `/dp/ASIN`、`/gp/product/ASIN` 商品路径，拒绝搜索页、店铺页、短链。
- 从商品 HTML 与 JSON-LD 提取名称、品牌、品类、价格、功能要点、规格表、主图。
- 识别**多型号商品**的当前型号与可选型号总数，绝不借用其他型号的价格。
- 识别**价格缺失的真实原因**（地区不可配送 / 缺货 / 未解析到），并区别对待。
- 标注**非美元的本地化报价**（从非美国地区访问 amazon.com 会得到当地货币报价）。
- 通过 OpenAI 兼容接口生成中文分析与口播，强制引用证据编号。
- **内容质量检查**：10 条确定性规则，区分阻断级与提示级。
- **口播时长估算**：按每秒 5 字加标点停顿，核对"前 5 秒钩子"。
- **商品图片分析（可选）**：配置视觉模型后，把主图可见特征作为独立的 `V` 编号证据参与分析。
- 流式进度、随时取消、错误分类提示、一键复制文案。
- **用户账户与数据隔离**：邮箱注册登录，每个账号的分析记录、操作历史与积分互相不可见。
- **积分制**：注册赠 10 分，每次分析扣 1 分，失败自动退回。
- **操作历史与积分流水**：可查询、可对账，每笔扣费能追溯到具体的分析记录。
- **强制 HTTPS**：明文请求 308 跳转，并下发 HSTS 与内容安全策略。

**不包含**：第三方登录、密码重置邮件、支付充值、追价任务、自动化 CI/CD。

> 账户体系是可选的。不设置 `ACCOUNTS_DB` 时应用保持**单用户模式**：无需登录、不计积分、不留历史，与最初的纯工具形态完全一致。

## 核心设计：事实与推断分离

这是整个项目最重要的部分。

### 商品信息不经过 AI

抓取与解析是纯规则的（Cheerio 选择器 + JSON-LD），模型完全不参与。所有价格选择器都限定在**本商品的购买区容器内**，因为一个地区受限的页面仍然会渲染推荐位里其他商品的价格 —— 直接全页取"第一个价格"就会得到错价。

解析结果会转成带编号的证据列表：

```
F1  商品名称      Instant Pot Duo 6 Qt 7-in-1 Electric Pressure Cooker
F2  品牌          Instant Pot
F3  品类          Home & Kitchen / Kitchen & Dining / Small Appliances
F4  当前型号      6 Quarts
F5  可选型号数量  3 个
F6  页面价格      S$139.91
F7  页面功能描述  7 Cooking Functions: Pressure cook, slow cook, steam...
...
V1  图片可见特征  （仅在配置视觉模型时出现）
```

### 模型只能引用这些编号

发给模型的上下文**只有**这份证据列表。每条分析和口播都必须回引 `evidenceIds`，返回后逐项校验：

| 校验项 | 不通过的后果 |
| --- | --- |
| 引用了不存在的证据编号 | 拒绝 |
| 分析或文案非中文 | 拒绝 |
| 钩子超过 20 字 | 拒绝 |
| 钩子 + 正文超过 150 字 | 拒绝 |
| JSON 结构不符合 Zod 契约 | 拒绝 |

### 质量检查规则

结构合法之后还有一层内容检查，共 10 条规则：

| 规则码 | 拦的是什么 | 级别 |
| --- | --- | --- |
| `absolute_claim` | 绝对化措辞（最好、第一、唯一、完全不） | 阻断 |
| `guaranteed_effect` | 效果承诺（一定能、保证、必然） | 阻断 |
| `health_claim` | 健康功效声明（治疗、缓解疼痛、护脊） | 阻断 |
| `unsupported_number` | 材料里不存在的数字 | 阻断 |
| `unsupported_comparison` | 与同类产品的对比结论 | 阻断 |
| `price_claim` | 无价格时谈价格、划算、性价比 | 阻断 |
| `dropped_condition` | 丢掉前提条件（如"需搭配 X 使用"被省略） | 阻断 |
| `purchase_pressure` | 促单话术（速抢、错过就没了） | 提示 |
| `hook_too_slow` | 钩子估算超过 5 秒 | 提示 |
| `weak_citation` | 整句缺少有效证据支撑 | 提示 |

**阻断级问题会把具体的问题短语回传给模型要求改写**，最多 3 次模型调用。如果仍未修好，应用**如实返回 `passed: false` 与完整问题列表**，不擅自改写模型输出，也不假装通过。

`dropped_condition` 这条规则来自一次真实缺陷：早期版本为 Echo Dot 写的文案说"能扩展 WiFi 覆盖"，但页面原文的前提是"需已有 eero 网络"，压缩时前提丢了。

### 取不到就明确失败

| 情况 | 错误码 | 行为 |
| --- | --- | --- |
| 返回人机验证页 | `SOURCE_BLOCKED` | 停止，不生成分析 |
| 只有标题，缺功能和规格 | `INSUFFICIENT_PRODUCT_DATA` | 停止 |
| 页面 ASIN 与链接不符 | `PRODUCT_MISMATCH` | 停止 |
| 价格取不到 | — | `price` 为 `null` 并附原因说明 |
| 模型返回空内容 | `MODEL_EMPTY_RESPONSE` | 保留已取得的商品档案 |

模型失败时，**已经抓到的商品信息仍然可以查看**，不会整条丢弃。

## 技术栈

| 层 | 选型 | 版本 | 说明 |
| --- | --- | --- | --- |
| 框架 | Next.js（App Router） | 16.3.5 | 前后端同仓，API 路由跑在 Node 运行时 |
| UI | React | 19.3.0 | 单页交互，无状态管理库 |
| 语言 | TypeScript | 5.9.3 | `strict` 模式，`tsc --noEmit` 全量检查 |
| 数据校验 | Zod | 4.6.5 | 请求入参与模型返回的运行时契约 |
| HTML 解析 | Cheerio | 1.2.0 | 服务端 DOM 查询，不执行页面脚本 |
| 网络安全 | ipaddr.js | 2.5.0 | 校验解析出的 IP，阻断内网地址（SSRF 防护） |
| 数据库 | `node:sqlite` | 运行时内置 | 账户、积分、历史的持久化。**不新增依赖** |
| 加密 | `node:crypto` | 运行时内置 | scrypt 密码哈希、AES-256-GCM、常数时间比较 |
| 图标 | lucide-react | 1.46.0 | — |
| 测试 | `node:test` + tsx | 4.23.13 | 零额外测试框架，212 个用例 |
| 模型接口 | OpenAI 兼容 Chat Completions | — | 可换任意兼容服务商 |

**运行时要求**：Node.js ≥ 22.12.0。已在 **22.12.0** 与 **24.14.0** 两个大版本下实测通过全部测试、类型检查与生产构建。

几点选型说明：

- **为什么不用 Puppeteer/Playwright**：无头浏览器体积大、冷启动慢，且本项目需要的字段在静态 HTML 与 JSON-LD 中已经齐全。实测表明地区价格限制是**服务端 IP 决定**的，换成真实浏览器同样拿不到价格 —— 无头浏览器解决不了这个问题，只会增加部署成本。
- **为什么用 NDJSON 而不是 SSE**：需要推送的是结构化事件对象（阶段、商品档案、最终结果），NDJSON 逐行解析更直接。自实现的解码器按字节缓冲，**保证中文字符跨网络分块时不被截断**。
- **为什么不用 ORM**：只有 5 张表，手写 SQL 让"每个查询都带 `user_id`"这件事**肉眼可见**，比 ORM 的隐式作用域更容易审计；也省掉一整套 schema 与迁移工具链。
- **为什么密码用 scrypt 而不是 Argon2**：scrypt 由运行时内置，无需编译原生模块。加密库属于高风险依赖，能不引入就不引入。
- **为什么会话用数据库表而不是 JWT**：JWT 无法即时吊销 —— 改密码或封禁账号后旧令牌在过期前仍然有效。会话表删一行即生效。

## 快速开始

需要 Node.js 22.12+ 与 npm。

```bash
# 1. 安装依赖
npm ci

# 2. 配置环境变量
cp .env.example .env.local
# 编辑 .env.local，至少填入 OPENAI_API_KEY / OPENAI_BASE_URL / OPENAI_MODEL

# 3. 启动开发服务
npm run dev
```

打开 <http://localhost:3000>。

不配置模型也能打开页面查看界面与配置说明，但点击分析会提示 `MODEL_NOT_CONFIGURED`，**不会返回演示用的假数据**。

### 可用脚本

| 命令 | 作用 |
| --- | --- |
| `npm run dev` | 开发服务，改动即时生效 |
| `npm run build` | 生产构建 |
| `npm start` | 运行已构建的应用，默认端口 3000 |
| `npm test` | 78 个用例，全部离线，不访问真实商品或模型 |
| `npm run typecheck` | 严格 TypeScript 检查 |

> **重要**：`npm start` 运行的是**构建产物**。修改代码或 `.env.local` 后必须 `npm run build` 再重启，否则跑的还是旧版本。开发调试请用 `npm run dev`。

## 环境变量

所有变量**仅服务端读取**，不要加 `NEXT_PUBLIC_` 前缀。

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `OPENAI_API_KEY` | ✅ | 模型服务密钥 |
| `OPENAI_BASE_URL` | ✅ | 兼容接口根地址，**不要带 `/chat/completions`**；必须是 HTTPS |
| `OPENAI_MODEL` | ✅ | 模型名。需支持 Chat Completions、`response_format: json_object`、`max_tokens`、温度参数 |
| `OPENAI_VISION_MODEL` | | 支持图片输入的模型名，同一接口地址。留空则跳过图片分析 |
| `PRODUCT_SOURCE` | | `direct`（默认，直连公开页面）或 `firecrawl` |
| `FIRECRAWL_API_KEY` | | 选 `firecrawl` 时必填 |
| `PRODUCT_FETCH_ENDPOINT` | | 跨地区取价中转，必须是 HTTPS 且含 `{url}` 占位符 |
| `APP_ACCESS_TOKEN` | | 站点访问口令。**公开分享前强烈建议设置**，否则任何拿到链接的人都能消耗你的模型额度 |
| `ACCOUNTS_DB` | | 账户体系开关。`on` 使用默认路径 `.runtime/accounts.db`，也可填自定义路径；留空或 `off` 则保持单用户模式 |
| `HSTS_MAX_AGE` | | HSTS 有效期秒数，默认 `300`。验证无误后可调长，`0` 关闭 |

> 启用账户功能时，启动命令必须带上 SQLite 的实验性标志：
>
> ```bash
> ACCOUNTS_DB=on NODE_OPTIONS='--experimental-sqlite --disable-warning=ExperimentalWarning' npm start
> ```
>
> `node:sqlite` 是 Node 内置模块，但在 22/24 上仍需该标志才能加载。缺少它会导致账户相关接口返回 500。

`/api/status` 返回的 `modelConfigured: true` 仅表示**必填字段已填写**，不代表接口联网验证成功。

### DeepSeek 配置示例

```bash
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-flash
```

代码对这个**精确主机名**显式发送 `thinking: { type: "disabled" }`，不向其他供应商发送该私有参数。

> 这一条是踩过坑的：DeepSeek 的部分模型默认开启思考模式，推理内容会占满 `max_tokens` 预算，导致 `content` 返回空字符串 —— 表现为 `MODEL_EMPTY_RESPONSE`，看起来像 Key 失效，实际不是。
>
> DeepSeek 当前不支持图片输入，配置 `OPENAI_VISION_MODEL` 后会自动跳过图片分析，不影响主流程。

### 商品来源的限制

`direct` 不需要采集 Key，但 Amazon 可能返回访问确认页、验证码或不完整内容。应用会停止并说明原因，**不尝试绕过反爬机制**，也不会把 HTTP 200 当成抓取成功。

`firecrawl` 使用 `/v2/scrape` 的 `rawHtml` 输出，沿用同一套解析与身份校验。**尚未用真实账户验证**，服务覆盖范围与费用需自行确认。

支持的站点白名单在 `lib/amazon-url.ts`，这是**输入受理范围**，不是实测覆盖承诺。短链需先在浏览器展开再粘贴。

## 账户、积分与传输安全

### 数据表

| 表 | 存什么 |
| --- | --- |
| `users` | 邮箱、密码哈希、积分余额、启用状态 |
| `sessions` | 会话令牌的**哈希**、过期时间、登录环境（仅网段前缀） |
| `credit_transactions` | 每笔积分变动、变动后余额、原因、关联的分析 ID |
| `activity_logs` | 注册/登录/登录失败/分析等操作，含结果与错误码 |
| `analyses` | 商品档案、分析内容、质量报告 |

所有表都通过外键关联到 `users`，且带 `ON DELETE CASCADE` —— 删除账号会连带清除其全部数据。

### 数据隔离

隔离在**数据访问层强制**，不依赖调用方自觉：

```ts
findAnalysis(userId: string, analysisId: string)
//           ↑ 第一个参数必须是 userId，漏传编译不通过
```

- 每条查询都带 `AND user_id = ?`，**即使已知记录 ID**
- 越权访问返回 **404 而不是 403**，且与"记录不存在"返回**完全相同**的状态码与错误码 —— 403 会确认"这条记录存在，只是你没权限"，本身就是信息泄露
- 有专门的越权测试比对两种响应是否一致

### 积分的扣费时机

这是本功能最容易出错的地方。分析接口是**流式响应**，耗时 10–90 秒且中途可能失败（反爬拦截、模型超时、用户取消）。

采用**预扣 + 失败退回**：

```
1. 推流之前：校验余额 → 扣 1 分 → 写流水     ← 必须在这里
2. 执行分析
3. 失败 → 退 1 分 → 写退款流水
```

为什么必须在推流前扣：**一旦写入响应的第一个字节，HTTP 状态码就固定了**，再也无法返回 402。

几个关键细节：

- 扣费用 `UPDATE users SET credits = credits - 1 WHERE id = ? AND credits >= 1`，靠**影响行数**判断成功。不能"先查余额再扣"——两个动作之间会被并发请求插队，导致余额变成负数。
- 扣费与流水写入在**同一事务**内，不会出现余额变了而流水没记上。
- 唯一索引 `(user_id, reason, ref_id)` 保证重试既不会重复扣费，也不会重复退款。
- **退款范围**：采集失败、模型失败、超时、用户取消都退；**质量检查未通过不退**，因为模型 token 已真实消耗，且结果附带问题列表仍然可用。

### 密码与令牌

三种处理方式严格区分，不是都叫"加密"：

| 数据 | 处理 | 为什么 |
| --- | --- | --- |
| 密码 | **scrypt 哈希** | 永不需要还原。可解密存储是设计错误 |
| 会话令牌 | SHA-256 哈希 | 数据库泄露也无法拿去登录 |
| 需要还原的密钥 | AES-256-GCM | 只有必须取回明文的场景才用加密 |
| 商品分析结果、积分流水 | **不加密** | 公开数据，靠访问控制隔离。加密会让字段无法索引、排序与排查 |

防邮箱枚举做了三件事：失败信息统一为"邮箱或密码不正确"、**未注册邮箱也执行一次真实的 scrypt 计算**（否则响应快慢会暴露该邮箱是否存在）、登录失败按邮箱与网段**双维度**限速（只按邮箱可被用来锁死他人账号，只按网段则僵尸网络能绕过）。

会话 Cookie 带 `HttpOnly`（脚本读不到）、`Secure`（仅 HTTPS 传输）、`SameSite=Lax`（防 CSRF）。

### 传输安全

`proxy.ts` 在所有请求前执行：

- 明文 HTTP **308 跳转**到 HTTPS（308 保留请求方法与请求体，POST 不会被降级成 GET）
- 下发 `Strict-Transport-Security`，默认 300 秒
- 本地回环与私有网段豁免，否则本地开发与容器健康检查会被打断
- 代理场景下**以 `X-Forwarded-Host` / `Host` 判断主机名**，不能用 `request.url`——后者携带的是内部绑定地址，会导致线上永远不触发跳转

诚实的边界：**TLS 在平台边缘就终止了**，平台内部到本进程之间是明文 HTTP。这是所有 PaaS 的共同特征，应用层无法解决。本项目没有端到端加密，服务端能看到全部明文。

### 数据持久化的取舍

账户数据存放在容器本地的 SQLite 文件中。

> ⚠️ **容器被重建或重置时，账户与积分记录会全部丢失。** 这是当前部署方式的已知代价，适合演示，不适合真实用户数据。若要可靠持久化，应改用托管数据库（如 Neon、Supabase）—— 存储层是接口化的，替换实现不影响业务逻辑。

## 架构与数据流

```
浏览器
  │  POST /api/analyze  { url }   + session Cookie
  ▼
proxy.ts ── 强制 HTTPS → HSTS
  ▼
analyze-handler.ts ── 访问口令 → 鉴权 → 按账号限流 → URL 校验 → 90 秒总超时
  │
  ├─ 0. credits.ts         校验余额 → 预扣 1 分 → 写流水（事务）
  │                        余额不足在此返回 402，尚未开始推流
  │
  ├─ 1. source.ts          取 HTML（30 秒上限，4MB 上限，SSRF 防护）
  │                        direct 直连 │ firecrawl
  │
  ├─ 2. product-parser.ts  Cheerio + JSON-LD → 商品档案 + F 编号证据
  │                        身份校验、型号识别、价格原因判定
  │        │
  │        └─ vision.ts    （可选）主图 → V 编号证据
  │
  │     ◄── NDJSON 推送 { type: "product" }：此时前端已可展示商品档案
  │
  ├─ 3. generate.ts        证据列表 → 模型 → Zod 校验 → 结构校验
  │        │
  │        └─ quality.ts   10 条规则检查 → 阻断级问题回传改写（最多 3 次调用）
  │
  ├─ 4. ◄── NDJSON 推送 { type: "result" }：分析 + 口播 + 质量报告
  │
  └─ 5. 落库与结算          存分析记录 + 写操作历史
                           失败或取消 → 退回 1 分（幂等）
```

关键点：**商品档案先推送**。抓取成功但模型失败时，用户仍能看到完整的商品信息，而不是一个笼统的"AI 出错"。

前端解析 NDJSON 时按字节缓冲，中文字符跨分块不会乱码。

## 工程细节

### 超时与限流

| 项 | 值 |
| --- | --- |
| 整条分析总超时 | 90 秒 |
| 商品抓取超时 | 30 秒 |
| 模型单次调用超时 | 35 秒 |
| 图片分析超时 | 30 秒 |
| 模型最多调用次数 | 3 次（首次 + 最多 2 次修正） |
| 单进程并发上限 | 2 |
| 每分钟请求上限 | 10 |
| 请求体上限 | 4 KB（URL ≤ 2048 字符） |
| 页面抓取上限 | 4 MB |
| 图片大小上限 | 4 MB |

限流是**单进程内存计数**，多实例部署时不是全局限流。公网使用应配合 `APP_ACCESS_TOKEN` 与托管平台的额度保护。

### 字数统计口径

口播字数使用 **Unicode 码点**计数，包含钩子、正文、标点与中间换行，首尾空白不计，合计上限 150。钩子上限 20 字。

时长估算按**每秒 5 字 + 标点停顿 0.18 秒**。这是计算值，**不是真人朗读实测** —— 20 字的钩子在这个模型下必然落在 5 秒内，所以 `hook_too_slow` 实际很少触发。

### 安全防护

- **SSRF**：抓取前解析域名，用 `ipaddr.js` 校验目标 IP，阻断私有网段、回环、链路本地地址。重定向逐跳校验，有跳数上限。
- **图片来源白名单**：只接受 Amazon 官方图床域名，仅 `jpeg`/`png`/`webp`，4MB 上限。
- **不执行页面脚本**：Cheerio 只做静态 DOM 查询。解析内嵌 JSON 用的是手写的括号配对扫描，不用 `eval`。
- **提示注入**：模型拿到的是**已结构化的证据列表**，不是原始 HTML，且没有联网或工具调用权限。

### 错误码

34 个错误码，按来源分组：`INVALID_URL` / `NOT_PRODUCT_URL` / `UNSUPPORTED_MARKETPLACE` / `SHORT_URL`（输入）、`SOURCE_*`（抓取）、`PRODUCT_*` / `INSUFFICIENT_PRODUCT_DATA`（解析）、`MODEL_*`（模型）、`RATE_LIMITED` / `ACCESS_DENIED` / `TIMEOUT`（流程）。每个错误带 `retryable` 标记，前端据此决定是否提示重试。

这样做的目的是：出问题时能立刻知道是**链接、页面材料、模型还是最后的校验**环节，而不是笼统的"AI 出错"。

## 部署

本项目需要 Node 服务端运行 API，**GitHub Pages 等纯静态托管无法运行**。

### 方式一：Vercel（推荐）

推荐原因是它**可能**解决价格获取问题，并且提供稳定的长期在线。

Amazon 对判定为"无法配送到访问者所在地区"的商品**根本不下发价格** —— 页面 HTML 里就没有该商品的价格可解析。已确认从香港、新加坡出网时部分商品取不到价格，且两地结论一致，因此判断决定因素是**服务端出网 IP 所在地区**。

> ⚠️ **但"改从美国出网就能取到价格"尚未实测验证。** 这是基于上述现象的推断，不是已验证的结论。此外 Vercel 函数跑在数据中心 IP 上，Amazon 对这类 IP 的机器校验通常比家用或普通云主机更严格，**有可能出现价格能下发、但抓取被人机验证页拦住**的情况 —— 这两个问题是独立的。部署后请用实际商品链接验证，不要预设一定成功。

仓库中的 `vercel.json` 已把函数区域固定为美国东部：

```json
{ "regions": ["iad1"] }
```

步骤：

1. 打开 <https://vercel.com/new>，用 GitHub 登录并导入本仓库。
2. 框架会被识别为 Next.js，**保持默认构建配置，不要改成静态导出**。
3. 在 **Environment Variables** 填入 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`，建议同时设置 `APP_ACCESS_TOKEN`。变量**不要加 `NEXT_PUBLIC_` 前缀**。
4. Deploy，得到 `https://<项目名>.vercel.app`。
5. 访问 `/api/status` 确认 `modelConfigured` 为 `true`，再用不同品类的真实链接测试，重点看价格是否出现、是否出现采集受限提示。
6. 改环境变量后需 **Redeploy**；此后推送到 `main` 会自动重新部署。

注意事项：

- **Node 版本**：Vercel 当前默认 Node 24.x，且 `package.json` 的 `engines.node` 会**覆盖**项目设置。本项目的 `>=22.12.0` 属于开区间，会被解析为满足范围的最高大版本（即 24.x）。这已在 Node 24.14.0 下实测通过，无需额外配置；若要锁定 22.x，把 `engines.node` 改成 `"22.x"`。
- **限流会失效**：本项目的并发与频率限制是**单进程内存计数**。Vercel 是多实例 Serverless，实例之间不共享计数，因此限流形同虚设。公开分享前**务必设置 `APP_ACCESS_TOKEN`**，否则拿到链接的人可以不受限地消耗你的模型额度。
- Hobby 计划**只允许单一区域**，不要在 `vercel.json` 里再加区域，否则构建前就会失败。函数超时上限 300 秒，本项目设的 `maxDuration = 120` 在限额内。
- Hobby 计划有用量额度且不适用于商业用途。

### 方式二：任意支持 Node 的容器 / 云主机

```bash
npm ci && npm run build
npm start          # 已绑定 0.0.0.0，默认端口 3000
```

在平台的环境变量或项目根目录的 `.env.local`（建议 `chmod 600`）配置模型参数，然后把 3000 端口暴露出去。

注意两点：

- 沙箱类环境（Cloud Studio 等）**可能因休眠或重启丢失后台进程**，交付前请自己先访问一次确认。
- 本项目**没有 CI/CD**。推送到 GitHub 不会自动更新已部署的实例，需要重新拉取并重启。

### 演示建议（约 3 分钟）

正式演示前必须配置真实模型并确认至少一个链接跑通。

- **前 30 秒**：说明目标 —— 一个链接换来事实档案、用户价值分析和口播文案。
- **约 1 分钟**：展示抓取与分析阶段，打开原商品页核对名称、规格，说明缺失信息不猜测补齐。
- **约 1 分钟**：讲一条"功能 → 场景 → 用户收益"的分析链，展开对应证据；展示文案、字数、时长估算与复制功能。
- **最后 30 秒**：换一个不同品类的链接，或展示一个价格受限 / 无效链接的提示，说明没有为示例商品硬编码。

准备两个备选链接。共享屏幕时关闭环境变量、Key 管理与账单页面。

## 验收状态与已知限制

### 已验证

- **受控测试 212 项**，覆盖链接与 ASIN 校验、页面解析、字段缺失、型号识别、价格缺失原因与非美元标注、模型协议与自动修正、DeepSeek 参数隔离、10 条质量规则、时长估算、图片分析降级、字数、取消与事件流，以及加密、传输安全、账户、积分、数据隔离与真实数据库。这些是程序化断言，**不是 212 次真实模型调用**。
- 本地与远程运行环境均通过类型检查、生产构建与全部测试；Node 22.12 与 24.14 双版本验证。
- **真实商品端到端验证**：除题目两个示例外，另用瑜伽垫、Instant Pot（两款）、iPhone 保护壳、AirTag、Echo Dot 等不同品类链接实测走完采集 → 分析 → 口播，均通过结构校验与质量检查，钩子估算 1.6–2.8 秒。
- **账户与积分的真实 HTTP 验证**（非仅单元测试）：未登录分析返回 401 且不发起采集；注册返回 201 且赠 10 分，Cookie 具备 `HttpOnly`/`Secure`/`SameSite=Lax`；重复注册 409；错误密码与不存在的邮箱返回**完全相同**的提示；登录后分析成功且余额 10→9；操作历史与积分流水可对账，扣费流水的 `refId` 与分析记录 ID 一致；余额为 0 时返回 402 且不发起采集；失败请求不扣分。
- **跨账号越权验证**：用第二个账号持第一个账号的分析记录 ID 直接请求，返回 404，且与"不存在的 ID"响应完全一致；其历史、流水、分析列表均为空；记录所有者本人访问同一 ID 返回 200。
- **数据落盘核对**：5 张表数据正确写入，密码字段确认为 `scrypt$` 前缀的哈希而非明文。

### 已量化的限制

- **价格覆盖约三分之一。** 跨品类抽测 12 个商品：4 个取到价格，5 个因地区不可配送而**页面根本不下发价格**，2 个缺货，1 个 ASIN 失效。这不是解析失败 —— HTML 中确实没有该商品价格。应用会说明原因，不会借用推荐位或其他型号的金额。推测改从美国出网可覆盖这部分商品（或配置 `PRODUCT_FETCH_ENDPOINT` / Firecrawl），但**美区取价尚未实测验证**，另有 16 个公开中转服务实测全部失败。
- **价格货币随采集地区变化。** 从非美国地区访问 amazon.com 会得到本地化报价（如 S$、HKD），与美国访问者看到的美元金额不同。界面会标注，但**不做汇率换算**。
- **抓取成功率受反爬影响。** 同一链接可能偶发返回人机验证页，此时明确报错而不编造内容。
- **账户数据不持久可靠。** SQLite 文件在容器本地磁盘，容器重建即丢失（见上文取舍说明）。

### 未完成

- **图片分析的真实识别质量未验证。** 功能与降级路径已测试，但当前配置的 DeepSeek 模型不支持图片输入，需另配视觉模型才能评估效果。
- **质量检查是规则性的。** 能拦住绝对化措辞、效果承诺、材料外数字与前提条件遗漏，但**不做语义级事实核查**，也不核实页面宣传本身的真伪。
- **没有密码重置流程。** 忘记密码目前只能由维护者直接操作数据库。
- **限流是单进程内存计数。** 多实例部署下不是全局限流；积分提供跨实例的总量配额，但瞬时并发保护仅限本实例。
- 真实调用费用与延迟未做系统测量。
- 页面可访问不等于 AI 分析质量已被完整验收，发布前仍需人工抽查文案。
