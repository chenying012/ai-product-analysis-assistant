# 品析 · AI 产品分析助手

输入公开 Amazon 商品详情链接，整理商品信息、分析目标人群/场景/痛点/卖点，并生成 150 字以内的中文短视频口播。

## 当前交付范围

基础代码与接口配置入口已实现。**没有模型和商品采集接口时，网页可以启动并查看配置说明，但不会生成预设分析或假文案。** 配置真实模型后已在多个品类的商品上端到端验证（见文末验收状态）；调用费用与延迟未做系统测量，Amazon 的价格覆盖与抓取成功率存在已量化的限制。

- 严格校验支持的 Amazon 站点与 `/dp/ASIN`、`/gp/product/ASIN` 商品路径。
- 从商品 HTML/JSON-LD 整理名称、品牌、品类、价格、功能与规格；缺失字段保持未知。
- 支持直连公开页面，或使用自己配置的 Firecrawl 账户获取页面 HTML。
- 服务端通过 OpenAI 兼容 Chat Completions 接口生成中文分析和口播。
- 校验 JSON 结构、证据编号、中文、20 字以内开头钩子与合计 150 字上限；不合格时自动要求模型修正。
- **内容质量检查**：对生成文本做确定性核查——绝对化措辞、效果承诺、同类对比、健康功效、材料以外的数字，以及无价格时的价格与性价比结论。发现问题会附带具体问题要求模型改写；仍未修好则如实展示报告，不擅自改写模型输出，也不假装通过。
- **口播时长估算**：按每秒 5 字加标点停顿估算钩子与全文秒数，用于核对“前 5 秒钩子”。这是计算值，不是真人朗读实测。
- **商品图片分析（可选）**：配置 `OPENAI_VISION_MODEL` 后读取商品主图，把可见特征作为 `V` 开头的独立证据参与分析与文案，与页面文字事实分开标注。图片不可用或模型不支持时自动跳过，不影响主流程。
- **跨地区取价回退**：Amazon 对不可配送地区不下发价格，此时可通过 `PRODUCT_FETCH_ENDPOINT` 或 Firecrawl 从其他地区重取，并且只在 ASIN 一致时采用。
- 识别多型号商品的当前型号与可选型号数量，不借用其他型号的价格。
- 页面展示实际采集/生成进度、取消按钮、错误提示、来源信息、质量报告和文案复制。
- 没有数据库、登录账户、追价任务或自动部署。

## 本地启动

需要 **Node.js 22.12 或以上**及 npm。

1. 在仓库根目录执行 `npm ci`。
2. 将 `.env.example` 复制为 `.env.local`，在本地编辑；不要提交真实密钥。
3. 执行 `npm run dev`。
4. 打开 `http://localhost:3000`。

没有接口也可以先打开页面查看“接口配置”。变更 `.env.local` 后请重启服务。

可用 `node --version` 确认运行时版本；版本过低时请先切换到满足要求的 Node.js 22 LTS。项目不依赖开发者机器上的特定绝对路径。

## 接口配置

| 变量 | 用途 | 要求 |
| --- | --- | --- |
| `OPENAI_API_KEY` | 模型服务密钥 | 必填，仅服务端使用 |
| `OPENAI_BASE_URL` | OpenAI 兼容接口根地址 | 默认为 `https://api.openai.com/v1`，不要加 `/chat/completions`；必须是 HTTPS |
| `OPENAI_MODEL` | 服务商实际可用的模型名称 | 必填；需支持 Chat Completions、`response_format: json_object`、`max_tokens` 与温度参数 |
| `OPENAI_VISION_MODEL` | 支持图片输入的模型名称 | 选填；留空则跳过图片分析。需与上面同一个接口地址。DeepSeek 当前不支持图片输入，实测会自动跳过 |
| `PRODUCT_SOURCE` | 商品信息来源 | `direct`（默认）或 `firecrawl` |
| `FIRECRAWL_API_KEY` | 自己的 Firecrawl 密钥 | 选择 `firecrawl` 时必填；调用前确认服务条款与费用 |
| `PRODUCT_FETCH_ENDPOINT` | 跨地区取回商品页的中转地址 | 选填；必须是 HTTPS 且包含 `{url}` 占位符。仅在本地区不可配送导致页面无价格时使用 |
| `APP_ACCESS_TOKEN` | 本网站独立访问口令 | 本地可留空；公开分享前建议设置，不要填模型密钥 |

这里的“已配置”仅表示必要字段已填写，**不代表接口已联网验证成功**。不同兼容服务可能有模型/参数差异，不支持时会明确提示。

若选用 DeepSeek 官方接口，可设置 `OPENAI_BASE_URL=https://api.deepseek.com`、`OPENAI_MODEL=deepseek-flash`。程序对该精确主机名显式发送 `thinking.type=disabled`，不向其他供应商发送此私有参数。该参数已通过受控请求测试，实际模型权限、额度和内容质量仍需使用自己的有效配置验证；`OPENAI_` 前缀只是兼容接口命名。

在聊天或公开记录中出现过的 Key 建议先撤销轮换。新的 Key 只填入本地或云端的服务端配置，不需要发给网站访客，也不要提交到仓库。

### 商品来源的限制

`direct` 不要求采集 Key，但 Amazon 可能返回访问确认页、验证码、错误页或不完整内容。工具会停止并说明原因，不尝试绕过限制，也不会把 HTTP 200 当成商品获取成功。

2026-09-14 的早期通用 HTTP 客户端预检返回了“Continue shopping”页面；随后使用应用自身的 Node 采集模块，实际取得两个题目商品及一个 Echo 商品的详情（分别取得 11、13、8 条字段依据；未取得的价格保持为空）。这属于三次真实采集冒烟检查，**不是稳定成功率或所有 Amazon 站点的覆盖证明，也尚未验证真实模型生成**。

`firecrawl` 使用 `/v2/scrape` 的 `rawHtml` 输出，并沿用同一页面解析与身份检查。尚未用真实账户调用；服务覆盖、字段完整度、费用和访问权限仍需验证。托管服务也不保证每个商品都能获取。

当前支持的常见站点列表位于 `lib/amazon-url.ts`；这是输入支持范围，不是实测覆盖承诺。短链需先在浏览器展开，再粘贴最终商品详情地址。

## 运行检查

- `npm test`：合成 HTML 和注入的模型响应测试，不访问真实商品或模型服务。
- `npm run typecheck`：严格 TypeScript 检查。
- `npm run build`：生产构建。
- `npm start`：运行已构建的应用，默认端口 3000。

测试数据仅位于 `tests/`，生产应用不引用它们。没有 Demo 模式或失败后的假数据回退。

## 目录与流程

- `app/`：页面入口、全局样式和 API 路由。
- `components/product-assistant.tsx`：输入、设置指引、进度、商品/分析/文案展示。
- `lib/amazon-url.ts`：站点白名单与商品链接规范化。
- `lib/server/source.ts`、`product-parser.ts`：有界抓取与商品信息解析。
- `lib/server/generate.ts`：真实模型调用和最终内容校验。
- `lib/server/analyze-handler.ts`：业务流程、访问口令、限流、超时和增量事件。
- `lib/contracts.ts`、`event-stream.ts`：共享数据契约与中文安全的 NDJSON 读取。
- `tests/`：可离线运行的测试；`survey.md`：前期调研。

实际流程为：服务端请求校验 → 检查配置 → 获取商品 HTML → 验证材料并整理事实 → 模型分析/文案 → 校验 → 输出最终结果。模型失败时，已经取得的商品信息可继续查看。

## 内容与安全边界

- 页面事实与 AI 推断分开展示；证据编号检查只确认引用存在，不证明语义或商品功效完全真实，发布前仍需人工核对。
- 口播计数使用 Unicode 码点，包含钩子、正文、标点和中间换行；首尾空白不计。总计不超过 150。
- 钩子限制 20 字帮助控制开头长度，**实际 5 秒时长和吸引力需朗读检查**。
- 模型最多请求两次；商品获取上限 30 秒、模型单次上限 35 秒、整条分析上限 90 秒。
- 单进程最多并发两次分析、每分钟最多十次；多实例不是全局限流，公网使用应配合访问口令及托管平台的额度/流量保护。
- 密钥只从服务端环境读取，不写前端、输出或日志。`/api/status` 只返回非敏感配置状态。
- `.env.local`、缓存、依赖与运行产物已被 `.gitignore` 排除。工作区中的 `.codebuddy` 是项目记忆，不应清理。

## 项目是怎样工作的

这不是将 URL 直接交给模型的聊天套壳。前端和后端运行在同一个 Next.js 应用中：

1. **输入和安全检查**：服务端再次检查站点、HTTPS 和 ASIN，拒绝非商品链接；客户端校验只是体验优化。
2. **获取并整理事实**：Node HTTPS 或显式配置的 Firecrawl 获取 HTML；Cheerio 解析可见商品字段和 JSON-LD。识别到确认页、错配商品或材料不足时立即停止。字段保留来源编号，未知价格不补零。
3. **分析与写作**：服务端把本次事实交给模型，一次生成目标人群、场景、痛点、卖点和中文口播。要求区分页面事实与分析推断，模型没有执行页面指令或浏览任意网址的权限。
4. **应用层验收**：Zod 验证结构，程序检查引用编号、中文、钩子长度和150字总长。最多允许一次修正，失败不输出伪成功内容；这些检查不是独立的商品功效或语义真伪鉴定。
5. **结果与进度**：后端用 NDJSON 推送实际阶段，前端逐行解码，中文跨网络块不会被拆坏。抓取成功但模型失败时保留商品档案，支持取消和复制文案。

这种结构让采集来源和模型可分别替换，也方便在面试时演示：问题发生在链接、页面材料、模型还是最后校验，而不是统称“AI出错”。

## 怎样向别人展示（约3分钟）

**正式功能演示前必须配置真实模型并确认至少一个链接跑通。未配置版只能展示页面与配置/错误体验，不能称作完整AI演示。**

- **前30秒**：说明目标——输入一个商品链接，得到事实档案、用户价值分析和短视频口播。使用已经核验、演示时仍可访问的商品链接。
- **约1分钟**：展示采集和分析阶段，打开原商品页面核对名称、规格；说明缺失信息不会猜测补齐。
- **约1分钟**：讲一条“功能 → 使用场景 → 用户收益”的分析，展开对应的字段依据；展示中文文案、字数和复制功能，朗读钩子核对时长。
- **最后30秒**：换一个不同品类链接，或展示无效链接/访问失败提示，说明不是为示例商品硬编码。

准备两个不同品类链接作为备选，并明确说明失败原因；不要用测试fixture或录像替代对方要求的真实网址测试。共享屏幕时关闭环境配置、Key管理和账单页面。

## 部署到 Vercel（推荐，美国东部）

推荐这条路的原因是它同时解决两个问题：**商品价格**和**长期在线**。

Amazon 对判定为“无法配送到访问者所在地区”的商品**根本不下发价格**，页面 HTML 里没有该商品的价格可解析。若服务从香港、新加坡等地区出网，题目示例中的部分商品就取不到价格；从美国出网时 Amazon 会正常返回价格区。

仓库中的 `vercel.json` 已把函数区域固定为 `iad1`（美国华盛顿特区）：

```json
{ "regions": ["iad1"] }
```

Hobby（免费）计划**只允许单一区域**，因此不要在其中再添加别的区域，否则部署会在构建前失败。函数最长执行时间在 Hobby 上为 300 秒，本项目 `app/api/analyze/route.ts` 设置的 `maxDuration = 120` 在限额内。

部署步骤（用网页控制台即可，无需在任何对话或文件中粘贴访问令牌）：

1. 打开 <https://vercel.com/new>，用 GitHub 账号登录并授权，选择本仓库导入。
2. 框架会被识别为 Next.js，构建命令、输出目录保持默认，不要改成静态导出——本项目需要 Node 服务端运行 API。
3. 在 **Environment Variables** 中至少填写 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`；建议同时设置 `APP_ACCESS_TOKEN` 保护模型额度。变量只属于服务端，**不要加 `NEXT_PUBLIC_` 前缀**。
4. 点击 Deploy，等待构建完成，得到 `https://<项目名>.vercel.app` 网址。
5. 打开 `/api/status` 确认 `modelConfigured` 为 `true`，再用不同品类的真实商品链接测试，重点看价格是否出现、以及是否出现访问受限提示。
6. 修改环境变量后需要 **Redeploy** 才会生效。此后向 `main` 推送会自动重新部署，不必手工上传。

需要注意的两点：

- Vercel 函数运行在云服务商 IP 上。Amazon 对数据中心 IP 的机器校验通常比家用网络更严格，**可能出现返回人机验证页而不是商品详情**的情况。此时应用会明确提示采集受限，不会编造内容；如果频繁出现，需要改用 `PRODUCT_FETCH_ENDPOINT` 或 Firecrawl 之类的采集来源。区域固定为美区只解决“价格是否下发”，不保证抓取一定成功。
- Hobby 计划有用量额度且不适用于商业用途，作为作品演示足够。

## 如何部署到 Cloud Studio 并获得公网链接

`localhost` 只指访问者自己的机器，不能直接发送给面试官。GitHub 保存代码也不会自动运行本项目；**GitHub Pages 这样的纯静态托管无法执行这里的服务端API**。

部署需要在 Cloud Studio 的远程环境中持续运行 Node 服务，并把端口暴露为平台生成的 HTTPS 访问地址：

1. **准备发布内容**：使用已验证的项目版本，包含 `package.json`、锁文件、应用源码和构建产物；不要上传 `.env.local`、缓存、运行日志、`.git` 或个人项目记忆。
2. **准备运行时**：Node.js ≥22.12。有源码时先 `npm ci`、`npm run build`；使用与源码版本一致的预编译产物时只需安装相应依赖，保留完整 `.next`。
3. **配置服务端变量**：在远程环境设置模型地址、模型名和Key。也可在远程IDE中手动创建项目根目录的 `.env.local`，并限制读取权限。不要放到 `NEXT_PUBLIC_` 变量或前端代码。公开启用模型前建议设置独立 `APP_ACCESS_TOKEN`。
4. **运行网页**：启动命令为 `npm start -- --port 3000`；项目已绑定 `0.0.0.0`。平台转发3000端口后，以实际生成的网址为准，不手工拼接一个假域名。
5. **外部验收**：用无登录的浏览器或手机打开公网地址，检查首页、配置/错误体验及真实分析；在云端重新测试商品获取，因为云端网络与本机不同。
6. **发送给对方**：分享公网网页地址和GitHub仓库地址。如果设置访问口令，可通过合适渠道单独提供；**绝不提供模型API Key**。

Cloud Studio的沙箱/预览地址能否长期在线取决于实际套餐、运行状态与平台规则，不保证永久可用。正式提交前要确认环境不会休眠或到期；不要发送仅本人可见的IDE管理链接来代替网页链接。

本项目目前没有自动CI/CD。仅向GitHub推送不会自动更新已上传的沙箱，需要重新发布同一版本。重建或变更环境变量后要重启远程服务；不得停止其他人的进程。

## 验收状态与剩余事项

### 已验证

- **受控测试 78 项**，覆盖链接与 ASIN 校验、页面解析、缺失字段、型号识别、价格缺失原因与非美元标注、模型协议与自动修正、DeepSeek 参数隔离、内容质量规则、口播时长估算、图片分析降级、字数、取消与事件流。这些是程序化断言，**不是 78 次真实模型调用**。
- 本地与远程运行环境均通过类型检查、生产构建与全部测试。
- **真实商品端到端验证**：除题目两个示例外，另用瑜伽垫、Instant Pot（两款）、iPhone 保护壳、AirTag、Echo Dot 等不同品类链接实测采集→分析→口播，均通过结构校验与内容质量检查，钩子估算 1.6–2.8 秒。

### 已量化的限制

- **价格覆盖约三分之一**。跨品类抽测 12 个商品：4 个取到价格，5 个因 Amazon 判定「不可配送到采集所在地区」而**页面根本不下发价格**，2 个缺货，1 个 ASIN 失效。这不是解析失败，页面 HTML 中确实没有该商品价格；应用会说明原因，不会借用推荐位或其他型号的金额。要覆盖这部分商品需从美国出网或配置 `PRODUCT_FETCH_ENDPOINT` / Firecrawl。
- **价格货币随采集地区变化**。从非美国地区采集 amazon.com 会得到本地化报价（如 S$、HKD），与美国访问者看到的美元金额不同，界面已标注，但**不做汇率换算**。
- **抓取成功率受反爬影响**，同一链接可能偶发返回人机验证页；此时明确报错而不编造内容。

### 未完成

- **图片分析的真实识别质量未验证**：功能与降级路径已测试，但当前配置的 DeepSeek 模型不支持图片输入，需另配支持视觉的模型才能评估效果。
- **内容质量检查是规则性的**，能拦住绝对化措辞、效果承诺、材料外数字与前提条件遗漏，但不做语义级事实核查，也不核实页面宣传本身的真伪。
- 真实调用费用与延迟未做系统测量；长期在线取决于所用托管平台，页面可访问不等于 AI 分析质量已被完整验收。
